# Explain NEXUS in the viva

Start at backend/src/main/java/com/nexus. `domain/Rules.java` is plain Java: priority multiplication, SLA comparisons, guarded transition validation, Jaccard set similarity, BFS with queue/visited set. `domain/Account.java` is an abstract parent; each subtype overrides role(). `Incident.java` owns the lifecycle and methods acknowledge/resolve/verify/close. `strategy/AssignmentStrategy.java` describes eligible candidate and decision records plus a ranking contract; the two implementations override ranking. Runtime dispatch changes how the same candidate set is sorted. `service/IncidentService.java` composes repository, strategies and event publisher. `event/EventListeners.java` independently handles auditing and notifications (Observer). `data/` is Repository pattern via generic JpaRepository. `web/` maps HTTP DTOs, validation and role-scoped data. `security/` provides bcrypt, session and CSRF. `frontend/src/main.jsx` renders the role-specific experience, charts and dependency graph. No priority or assignment authority lives solely in the browser.

Complexities: candidate sorting O(T log T), token overlap O(words) expected, graph O(V+E) per BFS, prototype scans all incidents for scoped filtering/workload. A scaled system would page and aggregate queries, use DB indexes and dedicated workers. Discuss risk: demo cloud sleeps, no genuine infrastructure monitoring, no production security claim. All group members should understand data and demonstrate actual contribution; do not invent authorship.
